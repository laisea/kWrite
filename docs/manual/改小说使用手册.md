# 改小说使用说明

> 适用版本：截至 2026-05-14 的当前仓库实现
> 适用对象：已有 TXT 原文，希望按章节完成摘要、识别、改写、审阅和导出的用户

---

## 1. 改小说适合什么场景

改小说模式适合已经有完整原文的项目。它的目标不是从零写新书，而是把已有 TXT 拆成章节，再按"摘要 → 标记 → 改写 → 审阅 → 导出"的流程完成扩写、润色、风格统一或结构化改写。

| 模式 | 适合什么 | 不适合什么 |
| --- | --- | --- |
| 改小说 | 已有 TXT 原文，要分章改写或扩写 | 从零搭建创作蓝图 |
| 写小说 | 从创意、蓝图、章纲开始写新书 | 已有整本原文要按章节改写 |
| MaxWrite | 管理 2000+ 章超长篇结构和窗口 | 常规章节的日常改写 |

---

## 2. 整体流程图

```
新建项目 → 选择改小说 → 导入 TXT 原文 → 拆分章节 → 预览并校正章节 → 选择模型 → 选择提示词 → 确认创建
                                                                                                                          ↓
改小说工作流 5 阶段：
章节拆分 → 生成摘要 → 标记改写 → 执行改写 → Review-first 审阅 → 合并导出

持续辅助能力：
素材库 / 提示词快照 / 章节版本 / 质量检查 / Zen 全屏精修
```

---

## 3. 工作台长什么样

改小说工作台是桌面端三栏结构：左边定位章节，中间干活，右边看原文、改写、审阅、版本和辅助信息。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶部流程条：章节拆分 → 生成摘要 → 标记改写 → 执行改写 → 导出       [运行] [设置] │
├───────────────┬───────────────────────────────────────────────┬──────────────┤
│ 左侧章节列表   │ 中央阶段工作区                                │ 右侧详情/工具 │
│ 搜索 / 筛选    │ 阶段说明、状态、批量操作、当前章节主内容       │ 原文 / 改写   │
│ 章节状态徽标   │ 摘要卡片、识别结果、改写编辑器、审阅面板       │ 版本 / 质量   │
│ 多选批处理     │ 导出总检、格式选择、风险提示                 │ 素材 / 日志   │
├───────────────┴───────────────────────────────────────────────┴──────────────┤
│ 底部状态栏：当前阶段 / 已处理章节 / 失败数 / Token 用量 / 保存状态             │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 干嘛用的 | 你会经常干啥 |
| --- | --- | --- |
| 顶部流程条 | 看看现在到哪个阶段了 | 运行阶段、停止、看日志、打开设置 |
| 左侧章节列表 | 快速定位章节和批量选择 | 搜索、筛选、切换章节、批量处理 |
| 中央阶段工作区 | 干当前阶段的活 | 生成摘要、识别、改写、审阅、导出 |
| 右侧详情/工具 | 对照、版本和风险判断 | 看原文、改写、版本、质量检查 |
| 底部状态栏 | 持续反馈 | 看进度、失败数、Token 和保存状态 |

## 4. 开始新项目

点击项目列表右上角的 `新建项目`，选择 `改小说`。

### 4.1 第一步：导入文稿

把小说文本文件拖进窗口，或者点击选择文件。系统会自动识别编码，支持 `UTF-8 / GBK / GB18030 / Big5 / UTF-16`，如果识别错了可以手动切换。

导入后，下方会显示文件内容预览。

---

### 4.2 第二步：拆分章节

设置拆分规则。有两种方式：

- **按格式拆分**：输入章节标题的前缀，比如 `第`，或者勾选常见格式
- **按正则拆分**：直接写正则表达式，比如 `第[一二三四五六七八九十百千]+章`

右侧会实时预览拆分后的章节列表。确认没问题后进入下一步。

---

### 4.3 第三步：预览章节

系统会根据拆分结果重建章节列表。你可以：

- 调整章节顺序
- 合并或删除章节
- 修改章节标题

这是最后一次核对章节边界的机会。

---

### 4.4 第四步：选择模型

选择一个可用的 AI 模型。如果列表为空，需要先去 `模型管理` 页面添加。点 `连接测试` 确保模型服务正常。

---

### 4.5 第五步：选择提示词

选择一个改写用的提示词模板。系统内置了几个常用模板，你也可以在 `提示词管理` 页面自己修改或新建。

---

### 4.6 第六步：确认创建

检查项目名称、描述、章节数量、模型和提示词。确认后点 `创建`，进入工作流页面。

---

## 5. 工作流

工作流分为五个阶段，按顺序执行。

### 5.1 阶段一：章节拆分

确认章节边界。如果前面预览时已经调好，这一步可以直接点 `开始`。

---

### 5.2 阶段二：生成摘要

点 `开始` 让 AI 为每个章节生成摘要。可以批量处理，也可以单独对某章重新生成。

生成的摘要会在章列表中显示，后续改写时会用上。

---

### 5.3 阶段三：标记改写

AI 会逐章扫描，标记出哪些段落需要改写，哪些保留。标记结果显示在每一章下方，你也可以手动修改决策：`保留 / 改写 / 待定`。

---

### 5.4 阶段四：执行改写

进入改写阶段后，有两种模式：

- **批量模式**：一次性处理所有标记为改写的章节
- **单章模式**：逐章处理，每章改完后可以预览和修改

改写过程中，界面右侧会实时显示 AI 生成的文本。你可以随时接受或拒绝。如果开启对照模式，会同时显示原文和改写结果，方便对比。

每章可以保存多个版本，需要时回退。

**审查模式**：开启后，AI 会先给出修改建议，你确认后再应用，适合对质量要求较高的场景。

---

### 5.5 阶段五：导出

全部改完后进入导出页面。支持导出为：

- TXT
- Markdown
- JSON
- EPUB
- DOCX
- ZIP
- PDF

选择格式，点 `导出`，选择保存位置。

---

## 6. 其他操作

### 6.1 继续已有的项目

从项目列表点击项目卡片，选择 `继续工作流`，会从上一次中断的阶段继续。

### 6.2 编辑项目信息

在项目卡片上点 `编辑`，可以修改名称、描述、替换提示词模板或模型。

### 6.3 版本管理

每个章节的改写结果会自动保存为版本。在章节编辑区右侧可以查看历史版本，随时恢复。

### 6.4 素材库

在 `素材库` 页面可以添加角色卡、世界观设定、专业术语等，这些素材会在 AI 改写时作为参考，提升一致性。

### 6.5 质量检查

在工作流顶部有 `质量检查` 按钮，会扫描全文，找出重复段落、违规词、长度异常等问题。

---

## 7. 推荐使用节奏

1. 导入后先确认编码和章节边界，别急着跑 AI
2. 摘要阶段先批量跑完，再抽查重点章节
3. 标记改写阶段把低置信度段落留在 `待定`，人工复核后再进入改写
4. 执行改写时先用单章模式打样，确认风格稳定后再批量
5. Review-first 适合高质量项目，接受建议前先看原文对照
6. 导出前先清理未完成、待审阅和质量检查风险
